三、缺陷清单

🔴 P0 — 核心功能完全不可用

P0 B1｜OSS 上传接口未实现，前端 /upload/token 打空

证据：POST /upload/token（带有效 token）返回 50000；后端 13 个 Controller 中无任何 upload/media 控制器；application.yml 里也没有 oss.* 配置。

影响：发布二手、发帖、换头像三条业务线的媒体上传全部失效（前端 api/upload.uts 直传流程第一步就断）。

P0 B2｜发布二手 / 发帖必然失败（B1 的连锁后果）

后端 TradeServiceImpl.validateMedia() 与 ForumServiceImpl.validateMedia() 强制"images 与 videoKey 至少其一"，否则 40001「图片与视频至少上传其一」。

因 B1 用户永远传不上图 → 提交必被拒。前端两个发布页也没有"必须至少一张图"的前置校验，用户得填完整页才吃到报错。结论：这两个发布页目前 0 可用。

P0 B3｜论坛"发表评论"100% 失败（前后端契约不一致）

前端 forum/detail.uvue:179 const replyToCommentId = ref(0)，第 464 行调用 addComment(id, draft, 0) → 非回复场景发出 replyToCommentId: 0。

后端 ForumServiceImpl.java:335-338 拿到非 null 的 0 后 selectById(0) → 查不到 → 抛「被回复的评论不存在」。

实测：传 0 → 40001；不传该字段或传 null → code=0 成功；回复真实评论 ID → 成功。即"顶层评论必然失败，只有回复某条评论才行"。

P0 B4｜站内信（消息中心）整块是假数据，未接任何接口

证据：message/index.uvue:39-45 写死 5 条消息；message/chat.uvue:107-129 按 type 写死 4 条气泡。两个文件没有任何 import ... from api/。

未接接口：sendMessage / getMessages / getConversations / getUnreadCount 四个前端函数零调用（后端接口本身都正常）。

更严重：trade/detail.uvue 与 task/detail.uvue 已真实调用 createConversation 建好会话，再跳到 /pages/message/chat?conversationId=xx——但 chat.uvue 的 onLoad 只读 type、完全忽略 conversationId，于是展示假消息。用户看到的"联系卖家 / 联系负责人"是假的。聊天页对方昵称也是写死的（"王老师"/"平台客服"/"卖家"）。

🟠 P1 — 功能缺失 / 入口缺失

P1 B5｜"拉黑用户"全站没有入口

前端定义了 blacklistUser 但无任何页面调用；message/chat.uvue:141-143 的"···"菜单虽列了"拉黑用户"，但 uni.showActionSheet 没有 success 回调，点了没反应。现状：黑名单页只能"看列表 + 解除"，永远拉黑不了人。

P1 B6｜埋点上报（需求要求的 5 事件）未落地

前端 reportEvents（POST /analytics/events）零调用。需求文档写明"埋点 5 事件必须随 MVP 版本带上"，目前 App 端一个都没上报。

P1 B7｜未读数轮询未实现

getUnreadCount 零调用；后端 UserServiceImpl.getSummary() 里 unreadCount 硬编码返回 0。需求要求"会话页 5s / 前台 30s 轮询"，目前无轮询逻辑，"我的"页未读角标恒为 0。

P1 B8｜广告位功能不完整

后端 FeedItemVO 注释写明"本轮恒为 POST"——实测 /forum/feed 返回 4 条全部 itemType=POST，不返回任何 AD 素材。前端 trade/index.uvue:6、task/index.uvue:6 注释自认"未定义素材拉取接口，暂作占位"。附带：前端曝光上报用 action='EXPOSURE'（forum/index.uvue:206），而后端要求的枚举是 IMPRESSION。

🟡 P2 — 健壮性与质量

P2 B9｜单条广告上报无任何参数校验（可污染数据）

实测：{adId:1, slot:"GARBAGE", action:"GARBAGE"} → code=0 直接入库；同样的值走批量形态 → 40001 正确拦截。根因：AdReportDTO 的 @Pattern 只加在内部类 Item 上，单条形态的顶层字段没加约束。叠加 B8，前端上报的 EXPOSURE 会被原样写库，统计口径对不上。

P2 B10｜404 被吞成 50000，无法区分"接口不存在"与"服务器错误"

实测：未知路径（带有效 token）→ 50000 服务器内部错误。根因：GlobalExceptionHandler 的 @ExceptionHandler(Exception.class) 兜底把所有异常统一映射成 SERVER_ERROR——这也正是 B1 被"掩盖"成 50000 而非 404 的原因，排查时容易误判。

P2 B11｜聊天页"举报 / 拉黑"菜单点了没反应

uni.showActionSheet 无 success 回调，选项不生效（与 B5 同源）。

P2 B12｜死代码页

pages/index/index.uvue 是 uni-app 默认 Hello 模板，未被 pages.json 注册，也没有任何页面跳转过来，可直接清理。

四、修复建议（按顺序）

第一步 · 必须先做（否则发布类功能一直挂）

  1. 补 /upload/token 接口：新建 upload 控制器 + oss.* 配置。要点：需登录态；返回 uploadUrl（带签名的 PUT 地址）、fileKey、headers，字段名必须和前端 api/upload.uts 读的完全一致。先别接真 OSS——本地先返回一个 Mock 地址把链路跑通，再换真签名。
  2. 发布页加前置校验：两个发布页提交前先判断"是否有图片或视频"，没有就本地提示。注意后端是"至少其一且不能同时有"两条规则。

第二步 · 契约对齐（小改动）

  1. 修评论的 0 值问题：推荐改前端——replyToCommentId 为 0 时传 null 或不传；同时后端把 replyToId != null 收紧成 replyToId != null && replyToId > 0。两边都改最稳。
  2. 统一广告上报枚举：前端 EXPOSURE → IMPRESSION；给 AdReportDTO 顶层 slot/action 补 @Pattern，堵住单条形态校验漏洞。

第三步 · 功能补齐（工作量较大）

  1. 接入站内信：消息列表用 getConversations 替换写死数组（注意返回结构 {conversationId, peer, lastMessage, lastTime, unreadCount}）；聊天页 onLoad 读 conversationId，用 getMessages 拉历史、sendMessage 发送；对方昵称头像从会话数据取。轮询用 getUnreadCount（会话页 5s、前台 30s、退后台停）。
  2. 补"拉黑"入口：聊天页菜单 / 帖子详情 / 物品详情加"拉黑用户"，接 blacklistUser，并给 showActionSheet 补 success 回调。
  3. 接埋点：App 启动、页面浏览、发布成功、广告曝光 / 点击五处调 reportEvents。
  4. 广告素材：需后端在信息流真正下发 AD 条目（含 ad 子对象），依赖产品先补全"素材拉取接口"定义。

顺手清理

  1. 删掉 pages/index/index.uvue 死代码页。
  2. 给 GlobalExceptionHandler 单独加 404 分支（NoResourceFoundException），别再让不存在的接口伪装成"服务器内部错误"。
