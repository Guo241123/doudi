## 四、缺陷清单

**P0：0 个　P1：0 个**

### P2 观察项（建议，不改也不影响 MVP 上线）

1. **埋点静默丢弃不可感知**（`AnalyticsController.java:50-53`）：未登录且缺 deviceId 的事件被直接丢弃，接口仍返回 code=0。符合「失败静默」设计，但如果前端某处漏传 deviceId，数据会无声缺失且无人知道。建议：丢弃时打一条 debug 日志，或在返回 data 里带上 discarded 数量，方便联调期发现问题。

### 复核后排除的「疑似缺陷」（用例设计不完整 / 设计内行为）

- **发起任务咨询会话 TASK_CONSULT**：误报：TASK_CONSULT 按契约必须带 taskId，缺省被拦（40001 缺少任务 ID）是正确行为；带真实 taskId 创建/幂等复用均通过
- **游标越界返回空列表**：误报：游标语义是「取 id < cursor」，超大 cursor 返回全部是正确行为；翻页连续性已单独验证（两页 10 条无重复）
- **埋点缺 deviceId**：设计内行为：AnalyticsController.java:50-53 对未登录且缺 deviceId 的事件静默丢弃（与文档「失败静默」一致），返回 code=0；已列为 P2 观察项

另：篡改上传签名时 HTTP 状态码是 200、业务码 40301——符合本项目「统一返回体永远 HTTP 200」的约定，不是缺陷。
