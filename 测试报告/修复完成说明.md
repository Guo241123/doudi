## 一、后端修复

| **B3** | 顶层评论 100% 失败（前端传 `replyToCommentId: 0`，后端拿 0 当真实评论 ID 查库） | `ForumServiceImpl.comment()` 收紧为 `replyToId != null && replyToId > 0`，`0`/负数一律视为"非回复"。前端保持原样即可 |

| **B7** | `/user/summary` 未读数硬编码返回 0 | 接真实 Redis 未读计数器；`UserServiceImpl` 用显式构造 + `@Lazy` 注入 `MessageService` 打断循环依赖 |
| **B9** | 单条广告上报（`{adId, slot, action}`）**无任何校验**，传垃圾值也入库 | 顶层字段补 `@Positive` / `@Pattern`，并加 `@AssertTrue` 保证"至少一组完整上报"；与 `items[]` 批量形态校验口径一致 |
| **B10** | 未知路径被全局异常兜底吞成 50000「服务器内部错误」 | 新增 `NoResourceFoundException` / `NoHandlerFoundException` 分支，返回 `40401 请求的接口不存在，请检查路径是否正确`（这正是 B1 被误判成"服务器错误"的原因） |

## 五、前端静态校验（我做过的检查）

uni-app x 的完整编译只能在 HBuilderX / 真机上进行（CLI 的 `launch app-android --compile true` 在纯命令行模式下会秒停，不产生编译产物），所以我用了两层静态校验兜底：

1. **语法检查**：用 HBuilderX 自带的 TypeScript 编译器，对 14 个改动文件逐个做语法解析（`transpileModule` 报语法错误）→ **全部通过**
2. **导入检查**：逐个校验 `import { ... } from '相对路径'` 的路径真实存在、具名导出真实存在，并检查页面用了 `onLoad/onShow/onHide/onUnload` 是否已从 `@dcloudio/uni-app` 导入 → **全部通过**

另外顺手修了一个隐患：跳转聊天页时把对方昵称/任务标题拼进 URL 没做编码，含中文或 `&`、`=` 的昵称会破坏参数。已统一加 `encodeURIComponent`，会话页 `decodeURIComponent` 解回。

> 结论：语法与导入层面无问题。但**完整编译仍需你在 HBuilderX 里跑一次**（UTS 的类型系统比 TypeScript 更严格，某些类型问题只有完整编译才能暴露）。

## 六、你需要做的事

1. **在 HBuilderX 里重新编译运行前端**（改了 20 个前端文件，需真机/模拟器验证一次）。
2. 本地存储目录：`app/backend/backend/data/upload`（启动时自动创建）；图片走 `http://<后端地址>:8080/files/<fileKey>`。
   真机调试时后端地址仍是 `app/frontend/uniappx/uniappx/api/request.uts` 里的 `BASE_URL`，需与电脑同一 WiFi。
3. 后端启动命令（本次使用的）：
   ```
   DB_USERNAME=root DB_PASSWORD=<你的MySQL密码> java -jar target/backend-0.0.1-SNAPSHOT.jar --server.port=8080
   ```
4. 上线前把 `application.yml` 的 `storage.provider` 改为 `oss` 并配置 `oss.*`，上传即切到真 OSS，业务代码零改动。
