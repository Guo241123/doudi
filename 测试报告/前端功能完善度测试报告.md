## 2. 接口联调测试结果（真实打后端）

### 2.1 全部通过（节选，共 72 条）

**账号体系**：图形验证码、短信发送（含三重限频）、注册全流程（短信→校验→密码→昵称）、密码登录、短信登录、密码错误提示、重置密码、修改密码、更换手机号、注销账号、退出登录后 token 黑名单即时失效——**全部通过**。

**敏感词**：发帖含"赌博" → 40002 拦截正确。

## 3. 缺陷清单（按严重度排序）

### 🔴 P0 — 核心功能完全不可用（4 项）

**B1｜OSS 上传接口未实现，前端 `/upload/token` 打空**
- 证据：`POST /upload/token`（带有效 token）返回 `50000 服务器内部错误`；后端 13 个 Controller 中无 upload/media 控制器；`application.yml` 中也没有任何 `oss.*` 配置。
- 影响面：**发布二手、发帖、换头像**三条业务线的媒体上传全部失效（前端 `api/upload.uts` 的整个直传流程第一步就断）。

**B2｜发布二手 / 发帖必然失败（B1 的连锁后果）**
- 证据：后端 `TradeServiceImpl.validateMedia()` 与 `ForumServiceImpl.validateMedia()` 强制"images 与 videoKey 至少其一"，否则 40001「图片与视频至少上传其一」。
- 现实：因 B1 用户永远传不上图 → 提交必被拒。前端 `trade/publish.uvue`、`forum/publish.uvue` 自身也没有"必须至少一张图"的前置校验，用户会填完一整页才吃到一个后端报错。
- 结论：**这两个发布页目前 0 可用**。

**B3｜论坛"发表评论"100% 失败（前后端契约不一致）**
- 证据：前端 `pages/forum/detail.uvue:179` `const replyToCommentId = ref(0)`，`第 464 行` 调用 `addComment(id, draft, replyToCommentId.value)` → 非回复场景发出 `replyToCommentId: 0`。
- 后端 `ForumServiceImpl.java:335-338` 拿到非 null 的 0 后直接 `selectById(0)` → 查不到 → 抛「被回复的评论不存在」。
- 实测：`replyToCommentId=0` → 40001；**不传该字段或传 null → code=0 成功**；回复真实评论 ID → 成功。
- 结论：**顶层评论必然失败，只有"回复某条评论"能成功**。

**B4｜站内信（消息中心）整块是假数据，未接任何接口**
- 证据：`pages/message/index.uvue:39-45` 直接写死 5 条消息数组；`pages/message/chat.uvue:107-129` 按 `type` 写死 4 条气泡。两个文件**没有任何 `import ... from api/` 语句**。
- 未接的接口：`sendMessage` / `getMessages` / `getConversations` / `getUnreadCount` —— 前端 4 个接口函数**零调用**（后端接口本身都正常）。
- 更严重：`trade/detail.uvue` 与 `task/detail.uvue` 已经**真实调用了 `createConversation` 建好会话**，然后 `navigateTo` 到 `/pages/message/chat?conversationId=xx`——但 `chat.uvue` 的 `onLoad` **只读 `type`、完全忽略 `conversationId`**，于是展示假消息。用户看到的"联系卖家/联系负责人"是假的。
- 聊天页对方昵称也是写死的（"王老师"/"平台客服"/"卖家"），没用真实会话数据。

### 🟠 P1 — 功能缺失 / 入口缺失（4 项）

**B5｜"拉黑用户"全站没有入口**
- 前端 `api/report.uts` 定义了 `blacklistUser`，但**没有任何页面调用**。
- `pages/message/chat.uvue:141-143` 的"···"菜单里虽然列了"拉黑用户"，但 `uni.showActionSheet` **没有 success 回调**，点了完全没反应。
- 现状：`my/blacklist` 只能"看列表 + 解除拉黑"，**永远拉黑不了任何人**。

**B6｜埋点上报（需求要求的 5 事件）未落地**
- 前端 `reportEvents`（对应 `POST /analytics/events`）**零调用**。需求文档明确"埋点 5 事件必须随 MVP 版本带上"，目前 App 端一个都没上报。

**B7｜未读数轮询未实现**
- `getUnreadCount` 零调用；后端 `UserServiceImpl.getSummary()` 里 `unreadCount` 硬编码返回 0。
- 需求要求"会话页 5s / 前台 30s 轮询"，目前无任何轮询逻辑，"我的"页未读角标恒为 0。

**B8｜广告位功能不完整**
- 后端信息流 `FeedItemVO` 注释写明"本轮恒为 POST"——实测 `/forum/feed` 返回 4 条全部 `itemType=POST`，**不返回任何 AD 素材**。
- 前端 `trade/index.uvue:6`、`task/index.uvue:6` 注释自认："产品文档未定义 App 端素材拉取接口，暂作占位"。
- 附带：前端曝光上报用的是 `action='EXPOSURE'`（见 `forum/index.uvue:206`），而后端文档/批量校验要求的枚举是 `IMPRESSION`。

### 🟡 P2 — 健壮性与质量（4 项）

**B9｜单条广告上报无任何参数校验（可污染数据）**
- 实测：`{adId:1, slot:"GARBAGE", action:"GARBAGE"}` → **code=0 直接入库**；同样的值走批量形态 `{items:[...]}` → 40001 正确拦截。
- 根因：`AdReportDTO` 的 `@Pattern` 只加在内部类 `Item` 上，单条形态的顶层 `slot/action` 字段没加约束。
- 叠加 B8：前端上报的 `EXPOSURE` 是文档未定义枚举，会被原样写进库，统计口径对不上。

**B10｜404 被全局异常处理器吞成 50000，无法区分"接口不存在"和"服务器错误"**
- 实测：未知路径 `GET /definitely/not/exist`（带有效 token）→ `50000 服务器内部错误`。
- 根因：`GlobalExceptionHandler` 的 `@ExceptionHandler(Exception.class)` 兜底把所有异常（含 Spring 的 404）统一映射成 SERVER_ERROR。这直接导致了 B1 被"掩盖"成 50000 而不是 404，排查时容易误判。

**B11｜聊天页"举报 / 拉黑"菜单点了没反应**
- `uni.showActionSheet` 无 success 回调，选项不生效（与 B5 同源）。

**B12｜死代码页**
- `pages/index/index.uvue` 是 uni-app 默认 Hello 模板，未被 `pages.json` 注册，也没有任何页面跳转过来，可直接清理。

## 4. 修复建议（按优先级，你按顺序改就行）

### 第一步（必须先做，否则发布类功能一直挂）
1. **补 `/upload/token` 接口**：在后端新建一个 upload 控制器 + `oss.*` 配置项。要点：接口需登录态；返回 `uploadUrl`（带签名的 PUT 地址）、`fileKey`、`headers` 三件套，字段名必须和前端 `api/upload.uts` 里读的完全一致（`uploadUrl` / `fileKey` / `headers`）。**先别接真 OSS**，本地可以先返回一个 Mock 地址把链路跑通，再换真签名。
2. **发布页加前置校验**：`trade/publish.uvue` 和 `forum/publish.uvue` 在提交前先判断"是否有图片或视频"，没有就本地提示，别让用户填完整页才吃后端报错。注意后端是"图片与视频**至少其一、且不能同时有**"两条规则。

### 第二步（契约对齐，都是小改动）
3. **修评论的 0 值问题**：两种改法二选一，**推荐改前端**——`forum/detail.uvue` 里当 `replyToCommentId` 为 0 时传 `null`（或干脆不传该字段）。如果改后端，要在 `ForumServiceImpl` 里把 `replyToId != null` 收紧成 `replyToId != null && replyToId > 0`。**两边都改最稳**。
4. **统一广告上报枚举**：前端 `EXPOSURE` 改成后端文档的 `IMPRESSION`；同时给 `AdReportDTO` 顶层 `slot`/`action` 也加上 `@Pattern`，堵住单条形态的校验漏洞。

### 第三步（功能补齐，工作量较大）
5. **接入站内信**：`message/index` 用 `getConversations` 替换写死的数组（注意后端返回是 `{conversationId, peer, lastMessage, lastTime, unreadCount}`）；`message/chat` 的 `onLoad` 要读 `conversationId`，用 `getMessages` 拉历史、`sendMessage` 发送；对方昵称/头像从会话数据取，别再写死。轮询用 `getUnreadCount`（会话页 5s、前台 30s、退后台停）。
6. **补"拉黑"入口**：在聊天页"···"菜单和/或帖子详情、物品详情加"拉黑用户"，接 `blacklistUser`，并给 `showActionSheet` 补 `success` 回调区分选项。
7. **接埋点**：在 App 启动、页面浏览、发布成功、广告曝光/点击这几处调 `reportEvents`，凑齐需求要求的 5 个事件。
8. **广告素材**：需要后端在信息流里真正下发 AD 条目（含 `ad` 子对象），前端 Banner 才能显示——这一步依赖产品先补全"素材拉取接口"的定义。

### 顺手清理
9. 删掉 `pages/index/index.uvue` 死代码页。
10. 给 `GlobalExceptionHandler` 单独加一个 404 分支（`NoResourceFoundException` / `NoHandlerFoundException`），别再让不存在的接口伪装成"服务器内部错误"。
