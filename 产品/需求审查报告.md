# 需求审查报告

**审查对象**：`需求.txt`（一句话需求速览）、`需求文档.txt`（V1.1 需求基线版）
**审查日期**：2026-10-09
**结论**：整体质量不错，业务边界清晰（只做信息撮合、不做支付、无接单流转），可以作为开发依据。但存在 **5 个必须先拍板的矛盾/缺口**，建议确认后再进入开发排期。

---

## 一、必须先确认的问题（高优先级，影响开发范围）

### 1. 「站内信」前后矛盾
- **4.5.4 联系管理员**：写了「站内信」或跳转第三方。
- **10.2 二期（P1）**：又把「站内信」排到二期。
- **矛盾**：如果站内信是二期的，那 MVP 阶段「联系管理员」就只能跳第三方（微信/QQ/电话），4.5.4 的说法就不成立。
- **建议**：二选一——要么 MVP 就做最简版站内信，要么明确 MVP 只做「跳转第三方 + 展示管理员联系方式」，把 4.5.4 改掉。

### 2. 「消息通知」在 MVP 阶段没有触达方式
- **4.5.3 消息通知**包含：审核结果、评论/回复提醒、举报处理结果、公告。
- **10.2 二期（P1）**才有「推送通知」。
- **矛盾**：MVP 没有推送，用户只能主动打开 App 才能看到消息通知，审核不通过这种关键结果用户可能永远看不到。
- **建议**：明确 MVP 的消息通知 =「App 内消息中心（进 App 才能看到）」，并把「审核结果」在"我的发布"页面上直接展示状态，双保险。

### 3. 「注销账号」不能是可选项
- **4.1.3** 把注销账号标为「可选，P1」。
- **问题**：国内应用商店上架审核和《个人信息保护法》都要求 App 必须提供账号注销入口，这个不能延后。
- **建议**：改为 MVP 必须（Must），做最简版（设置页里一个入口 + 提交后 N 天内处理）即可。

### 4. 评论审核口径没拍板
- **4.4.4**：评论「先发后审**或**敏感词过滤 + 人工复审」——一个"或"字留下两种做法。
- **4.7.2**：又写死「评论：敏感词过滤 + 先发后审」。
- **建议**：统一按 4.7.2 的口径执行（敏感词过滤 + 先发后审），把 4.4.4 的"或"删掉。论坛类 App 这是审核底线，不建议再选"纯先发后审"。

### 5. 全文没有埋点需求，数据看板会是空的
- **5.3.1 数据看板**要展示：用户数、日活、任务数、二手数、帖子数、评论数、举报数、广告点击。
- **问题**：日活、广告点击这类数据不会凭空出现，需要在 App 里提前埋点（记录用户打开、广告曝光、广告点击等事件）。全文一个埋点都没定义，上线后看板大概率没数据可看。
- **建议**：MVP 至少定义这几个埋点——App 启动、页面访问、广告曝光、广告点击、发布行为。另外「广告点击」数据来源要写清：接入穿山甲/优量汇后，点击数据在第三方广告平台报表里，自家看板统计的是"自家广告位的曝光/点击"还是"第三方收益"，口径要定。

## 二、建议优化的问题（中优先级，影响体验和风险）

| 编号 | 问题 | 建议 |
|------|------|------|
| M-01 | 接口响应时间 < 2 秒太宽松（7.1），2 秒的体验已经很差 | 核心接口（列表、详情）改为 < 1 秒，写清统计口径（P95） |
| M-02 | 先审后发没有时效承诺，管理员审核慢的话用户发的二手一直不展示，体验差 | 定审核时效：如「24 小时内完成审核，超时自动通过或提醒管理员」 |
| M-03 | 视频限制只写"限制大小和时长"（7.1），没有具体数值，开发没法做 | 写明：如视频 ≤ 100MB、时长 ≤ 60 秒（数值需确认，标注"估算"） |
| M-04 | 插屏广告"每日不超过 3 次"（4.6.1），没写是"每用户每日" | 补充口径：每用户每日 ≤ 3 次 |
| M-05 | 二手"已售"全靠卖家手动标记，卖家忘了标就一直显示"在售"，别人白联系 | 加机制：发布超过 30 天自动下架或提醒卖家确认（天数需确认） |
| M-06 | 8 个物品分类写死在需求里，但 Web 后台功能清单里没有"分类管理" | 分类应做成后台可配置（增删改、排序），否则改个分类要发版 |
| M-07 | 任务有"报酬/线下结算"，存在诈骗风险空间（举报分类里也有"诈骗"），但任务页没有风险提示 | 任务详情页加风险提示文案，如「平台仅展示信息，请自行甄别，切勿提前付款」 |
| M-08 | 物品详情直接展示微信/QQ/电话引导交易，iOS 审核对"引导站外交易/导流"比较敏感，有被拒风险 | 准备好审核说明材料；界面文案避免"交易""购买"字样，用"联系卖家"弱化 |

## 二（补）、第二轮补充发现（2026-10-09 晚间补充）

| 编号 | 问题 | 建议 |
|------|------|------|
| S-01 | **图片/视频审核是缺口**：全文审核手段只有"敏感词过滤"（文字）和人工审核，但用户会传头像、二手图、帖子图片/视频，违规图会直接展示 | 接入内容安全审核服务（如腾讯云/阿里云内容安全接口，按量付费），图片视频先机审后人审，补进 4.7.2 与非功能需求 |
| S-02 | **缺"拉黑"功能（iOS 上架硬要求）**：有用户创作内容的 App，苹果审核要求举报、屏蔽（拉黑）、内容过滤三类机制齐全，现在只有举报 | 用户主页/详情加"拉黑"，拉黑后互不可见、对方无法评论自己 |
| S-03 | **"积分"是悬空概念**：任务卡片展示"报酬 / 积分 / 线下结算说明"，但全系统没有积分功能（数据实体、我的页面都没有），用户会误以为有积分系统 | 需澄清：积分只是管理员填的文字展示，还是真做积分体系？前者写明"纯文字展示"，后者是大功能需单独立项 |
| S-04 | **未登录状态没定义**：未登录时能否浏览交易/任务/论坛？还是强制登录？影响首页流程和应用商店审核演示（审核员不会注册） | 建议游客可浏览，操作时（发布/收藏/联系）才要求登录 |
| S-05 | **联系方式公开裸奔的隐私风险**：物品详情明文展示微信号/手机号，可被爬虫批量收集，卖家会被骚扰 | 联系方式仅登录用户可见，点击"联系卖家"后显示 + 一键复制，不明文展示完整号码 |
| S-06 | **两个口径/成本小事**：①"日活"怎么算（打开算还是登录算）没定义，上线后数据对不上；②手机号验证码需购买短信服务，按条收费且要防短信轰炸 | ① 看板指标补口径定义；② 补短信服务预算与限频规则（如同号 1 分钟 1 条、1 天 5 条，数值需确认） |
