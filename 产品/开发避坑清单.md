# 开发避坑清单

**适用项目**：社区任务与二手交易 App（V1.2，MVP 单服务器架构）
**整理日期**：2026-10-09
**用法**：开发排期前过一遍；每条坑都写了"不避的后果"和"怎么做"，可以直接转给开发同学。

---

## 〇、最容易翻车的 Top 5

| # | 坑 | 不避的后果 | 怎么做 |
|---|----|------------|--------|
| 1 | 短信验证码接口不限频 | 被脚本刷短信，一晚上烧几千块短信费 | 同一手机号 1 分钟 1 条、每日 5 条；同一 IP 每日设上限；验证码随机 6 位、有效期 5 分钟、验证一次即作废 |
| 2 | 备份了但从没恢复过 | 数据库出问题时才发现备份是坏的，全站数据丢失 | 上线前真实演练一次"从备份恢复到新库"，验证能跑起来；之后每月演练一次 |
| 3 | 图片视频直接存服务器硬盘 | 磁盘一个月占满、带宽被原图拖死、列表加载极慢 | 全部走对象存储 + CDN；上传后服务端压缩再存（长边压到 1280px 左右、视频转码） |
| 4 | iOS UGC 三件套不全 / 引导站外交易 | 上架被拒，反复卡审核 | 举报 + 拉黑 + 内容过滤必须齐全（V1.2 已含）；文案用"联系卖家"，避免"购买/交易/支付"字样；给审核员提供演示说明 |
| 5 | 价格用小数（浮点）类型存 | 金额计算出现 0.1+0.2≠0.3 的误差，价格显示错乱 | 数据库里价格用整数"分"存，展示层再换算成元；排序、比较都在整数上做 |

## 一、架构与数据库

- **别把所有删除做成物理删除**：内容表加 `is_deleted` 软删除标记 + 创建/更新时间字段。审核申诉、举报追溯都靠原始数据，删了就说不清。
- **状态字段统一**：在售/已售、待审核/已通过/已拒绝等状态用固定的数字或枚举值，前后端和后台用同一套定义，别各写各的字符串。
- **单服务器至少做资源隔离**：数据库和 App 服务混部时，用容器或进程限制数据库内存/CPU 配额，防止一个慢查询把整台机器拖死。
- **慢查询日志上线第一天就开**：等用户说"卡"再查就晚了。
- **预留增长**：1 万用户没事，但表结构按 10 万的量设计索引（比如物品表的分类 + 状态 + 创建时间联合索引），免得半年后翻工。

## 二、内容审核

- **敏感词库做成后台可维护**：管理员能在 Web 后台增删敏感词，别写死在代码里——否则加一个词要发一次版。
- **机审会漏也会误杀**：内容安全 API（图片/视频/文字）有漏判和误判，UI 上要留"误判反馈"入口，管理员后台能一键恢复被误删内容。
- **先审后发要有时效承诺**：24 小时内审完（V1.2 已写），后台加"待审核"列表按时间排序、超时标红，不然堆积没人管。
- **头像也是内容**：用户头像同样过机审，别只审帖子和二手图。

## 三、iOS 上架

- **账号资质先行**：苹果开发者账号（公司账号更好）、穿山甲/优量汇的**企业资质**——个人开发者接广告 SDK 受限甚至接不了，这一条不确认，广告模块整个排期都是空的。
- **别碰热更新**：动态下发可执行代码是苹果红线，直接封号。
- **隐私政策 URL 必须真实可访问**：上架时填的链接，审核员真的会点开看。
- **ATT 弹窗**：接广告 SDK 前先弹 ATT 授权（iOS），顺序反了广告填充率几乎为 0。
- **审核演示材料**：写一页说明（怎么登录、哪里能看审核功能），游客可浏览模式已经帮你解决了大半。

## 四、登录与短信

- 短信签名和模板要**提前申请**，运营商审核要 1～3 天，别卡在上架前。
- 验证码发送接口必须**图形验证码或滑块前置**（哪怕最简版），纯接口裸奔必被刷。
- 手机号在数据库和日志里**脱敏存储/展示**（138****5678），日志里别打完整手机号——合规检查会看这个。

## 五、接口与安全

- **身份只从登录态取**：所有写操作（编辑/删除/收藏）服务端从登录凭证解析用户 ID，绝不信任前端传的 `userId`——否则任何人改个参数就能删别人的帖子（越权，最常见的安全事故）。
- **分页接口限制单页条数**：`pageSize` 上限 50，防一次拉全表。
- **上传文件校验**：校验文件真实类型（不是只看后缀名），用对象存储直传 + 回调确认，服务器不经手大文件。
- **管理后台**：强密码 + 登录验证码是底线；有条件加 IP 白名单；操作日志记录到具体管理员（V1.2 已写）。
- **卖家联系方式任何接口都不返回**：V1.2.1 起第三方联系方式选填、不公开展示，"联系卖家"走站内信；接口层面该字段也不下发给前端，防爬虫批量扒微信号。

## 六、交易与任务业务

- **超期自动下架**：二手发布超过 30 天自动下架或提醒卖家确认（天数待定），否则"已卖掉但忘了标"的僵尸在售信息会越来越多，用户白联系。
- **价格展示统一格式**：整数价不带小数点，带小数统一两位；"可议价"标签字段和价格分开存。
- **任务内容也有合规风险**：管理员发的任务同样别出现"刷单""先交押金"类描述，发布后台加一条提示文案给管理员自己看。

## 七、论坛与信息流

- **评论只做两级**：评论 + 回复（回复统一挂在被回复评论下），不做无限楼中楼——后端数据结构和前端展示复杂度都会翻好几倍。
- **信息流分页用游标**：按"最后一条的 ID/时间"翻页，不用页码。页码翻页在新内容插入时会重复/漏数据。
- **点赞防连点**：前端防抖 + 后端按"用户 + 内容"做唯一约束，同一用户对同一帖子只能点赞一次，取消再点不算新增。

## 八、流程与时间线（容易踩的节奏坑）

**主体资质结论：个体工商户可以走通全链路**——穿山甲/优量汇均支持个体户入驻（个人开发者不能变现），App/域名备案、软著、微信开放平台认证个体户均可办理。**个体户营业执照是整条链路的钥匙，最先办。**

| 事项 | 耗时 | 什么时候启动 | 备注 |
|------|------|--------------|------|
| 个体户营业执照 | 1～3 天 | **现在**（广告与备案的前提），经营范围含"软件开发/信息服务"类 | 广告结算账户：对公账户或经营者个人卡，入驻时与平台确认 |
| App 备案 + 域名备案 | 2～4 周 | **现在**，与开发并行 | 个体户主体可备案 |
| 苹果开发者账号 | 1～2 周 | 现在就办，个体户/公司名义优于个人 | 个人账号可上架但部分能力受限 |
| 软著申请 | 普通 1～2 个月 | 现在提交材料，不阻塞开发，上架前拿到即可 | 国内安卓商店基本必备；可付费加急 |
| 穿山甲/优量汇入驻 | 1～2 周审核 | 营业执照到手就提交 | 个人开发者不能变现，勿走个人通道 |
| 短信签名/模板审核 | 1～3 天 | 短信服务开通时立即申请 | |
| 微信开放平台认证（如需微信登录） | 约 1 周 | 需企业/个体户资质，个人不能认证 | 不做微信登录可跳过 |
| 内容安全审核服务开通 | 1 天 | 开发联调前 | 按量付费 |
| 隐私政策/用户协议文案 | 1～2 天 | 上架前需有可访问 URL，法务过目 | |
