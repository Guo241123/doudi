# 代码审查报告（全量）

> 审查日期：2026-10-13
> 审查范围：后端 Spring Boot 全部 Java 源码（约 200 个文件）、schema.sql、application*.yml、前端 uni-app X 全部页面与工具类、admin-web 目录现状
> 审查方式：逐文件通读 + schema 交叉核对 + Maven 编译验证（编译通过，退出码 0）
> 说明：行号以当前 main 分支（0634767）为准

## 总体评价

代码质量高于常见 MVP 水平，亮点：

- 列表接口全部批量装配（作者/媒体/点赞态一次查），无 N+1
- 游标分页口径全项目统一（`WHERE id < ? ORDER BY id DESC LIMIT size+1`）
- 点赞/收藏/拉黑靠数据库唯一键 `uk_user_target` 兜底幂等，并发正确性靠 DB 而非内存判断
- App 用户与管理员两套会话体系物理隔离（双拦截器 + client claim 强校验）
- 高危操作后统一清全部 token（换绑/改密/注销/重置）
- 注释中设计依据充分，与《接口文档》《避坑清单》条目可对上

但存在 **2 个上线阻断级、6 个高危**问题，以及一批中低危缺陷。以下按严重级别列出。

## 一、严重（上线前必须修复）

### 1. 短信服务 mock 在生产不会关闭，且真实实现是空壳

- 位置：`app/backend/backend/src/main/resources/application.yml:48`、`application-prod.yml`（未覆写）、`common/sms/MockSmsService.java:20`、`common/sms/AliyunSmsService.java:18`
- 问题：
  - `sms.mock-enabled: true` 写死在基础配置里，没有环境变量占位；`application-prod.yml` 没有覆写 → 生产仍走 Mock，验证码明文打进日志。任何能看日志的人可登录/重置**任意账号**。
  - 更根本的问题：`AliyunSmsService` 只是"抛异常占位"，短信通道实际从未接入。把开关关了服务也不可用。
- 修复建议：
  1. 基础配置改为 `${SMS_MOCK_ENABLED:true}`，prod 显式 `sms.mock-enabled: false`；
  2. 上线前完成阿里云签名/模板申请与 SDK 接入，替换占位实现；
  3. 增加 fail-fast：生产 profile + mock 开启时启动即报错。

### 2. 前端 BASE_URL 硬编码开发机局域网 IP

- 位置：`app/frontend/uniappx/uniappx/api/request.uts:9`
- 问题：`const BASE_URL = 'http://192.168.187.70:8080/api/v1'`，无任何环境区分。当前打的任何包，换网络环境后端即失联；同时为 HTTP 明文（生产应为 HTTPS）。
- 修复建议：按条件编译（`#ifdef APP-ANDROID` + 自定义 env）或构建配置区分联调/生产地址；生产走 HTTPS 域名。

## 二、高危

### 3. jwt.secret 带开发默认值，生产漏配即全线失守

- 位置：`application.yml:24`（`${JWT_SECRET:dev-secret-please-change-0123456789abcdef}`），且 `spring.profiles.active: dev` 为默认激活
- 问题：部署时漏配环境变量会用可预测密钥 → 可离线伪造任意用户甚至 ADMIN token（签名密钥与上传直传 HMAC 共用，见问题 4）。
- 修复建议：去掉默认值；启动时校验密钥长度（≥32 字节）与"非开发默认值"，不满足直接 fail-fast。

### 4. 上传直传接口无大小/类型限制、签名可重放

- 位置：`module/upload/controller/UploadController.java:49-56`、`module/upload/service/impl/UploadServiceImpl.java`
- 问题：
  - `request.getInputStream().readAllBytes()` 无上限，大文件直接 OOM；磁盘可被打满；
  - 不校验内容真实为图片/视频（扩展名是服务端定的，但字节内容任意，可作文件存储跳板）；
  - 同一签名 URL 在 600s TTL 内可重复使用（未消费一次性凭据）；
  - HMAC 密钥复用 `jwt.secret`（`UploadServiceImpl.java:47`），一类密钥泄漏殃及全部。
- 修复建议：加 Content-Length 上限（如图片 10MB / 视频 100MB）与 Spring multipart 限制；魔数校验文件头；签名加入随机 nonce 并在 Redis 记录一次性消费；上传签名独立密钥。

### 5. IP 限频可被伪造头绕过

- 位置：`common/util/IpUtil.java:16`
- 问题：无条件信任 `X-Forwarded-For` / `X-Real-IP`。客户端自带这两个头即可绕过短信 IP 限频（20 条/日）与登录 IP 限频（30 次/小时）。目前这两道防线只防"老实人"。
- 修复建议：仅在确认部署在可信反代（Nginx/SLB）之后才读转发头，并只信任最后一跳或配置的可信代理列表；否则用 `request.getRemoteAddr()`。

### 6. 换绑手机号只验证新号，会话被盗即永久丢号

- 位置：`module/user/service/impl/UserServiceImpl.changeMobile:101-121`
- 问题：只需新手机号的短信码，不验证旧手机号或登录密码。token 一旦被盗，攻击者改绑自己的手机 → 改密 → 永久接管，原主人失去全部找回手段。同文件的 `changePassword` 都要求原密码/短信二选一，换绑反而更松。
- 修复建议：换绑至少二选一验证：旧手机号短信码 或 登录密码。

### 7. 种子管理员密码哈希随仓库分发，且无改密接口

- 位置：`src/main/resources/db/schema.sql:293-295`、`module/admin/controller/AdminAuthController.java`（仅 login）
- 问题：admin 账号的 bcrypt 哈希公开在 git 里（可离线爆破）；后端没有管理员改密接口，上线忘改库即后台失守。
- 修复建议：种子管理员只用于联调，生产建库脚本去掉该 INSERT；后台增加改密接口；首次登录强制改密。

### 8. 免登上报接口可无限刷库

- 位置：`common/auth/AuthInterceptor.java:47-50`（游客放行 `/api/v1/ads/**`、`/api/v1/analytics/**`）、`module/ads/dto/AdReportDTO.java`、`module/analytics/service/impl/AnalyticsEventServiceImpl.java:56-58`
- 问题：
  - 两个上报接口无任何限频，可脚本刷曝光/点击/埋点，污染运营数据；
  - `AdReportDTO.items` 列表无 `@Size` 上限；
  - 埋点 `deviceId` 无长度校验（列宽 VARCHAR(64)），超长会使该条 insert 失败——flush 是逐条 insert 且 catch 整批丢弃，一条坏数据丢整批（最多 500 条）。
- 修复建议：`items` 加 `@Size(max=20)`；`deviceId` 加 `@Size(max=64)`；flush 改批量 insert + 单条失败跳过；按 IP 对上报接口做简易限频。

## 三、中危

### 9. 隐私政策/用户协议页打开的是 example.com

- 位置：`app/frontend/uniappx/uniappx/pages/common/webview.uvue:13-20`、`pages/my/settings.uvue:98`
- 问题：`url` 只初始化为 `'https://example.com'`，`onLoad` 只读 `title` 不读 `url`；调用方也只传 title。合规链接全是坏的（上线资质清单硬要求）。
- 修复建议：webview 页读取 `query['url']` 并校验协议白名单（仅 https）；调用方传入真实协议地址。

### 10. 会话复用竞态，可建出平行会话

- 位置：`module/message/service/impl/MessageServiceImpl.createConversation:104-131`；`db/schema.sql:339-355`（t_conversation 无唯一键）
- 问题：check-then-insert 无唯一键兜底。并发双击"联系卖家"会建两条会话，后续未读数/列表都会分裂。
- 修复建议：加唯一索引（TRADE 场景用 `LEAST/GREATEST` 生成对 or 应用层生成 dedup key 列）+ 捕获 `DuplicateKeyException` 返回已存在会话。

### 11. 评论分页热评重复出现

- 位置：`module/forum/service/impl/ForumServiceImpl.comments:277-283`
- 问题：前 3 条热评只在第一页的 `notIn(hotIds)` 里排除；翻第二页时（cursor 之后）第一页出现过的热评会再次出现。
- 修复建议：翻页时把当前已见热评 ID 集合随 cursor 传递，或第二页起对 `like_count>0 AND id IN (热评)` 的行做服务端过滤；更简单的方案是热评也走统一游标（热评条数少，影响可控）。

### 12. 注销清理的软删字段实际不生效（疑似，需单测验证）

- 位置：`job/DeactivateCleanupJob.java:58`
- 问题：`user.setIsDeleted(1)` 后走 `updateById`——MyBatis-Plus 开启逻辑删除后，`is_deleted` 会被排除在 UPDATE 的 SET 子句外（entity 层 `@TableLogic` 生效时）。目前靠"昵称改已注销/手机号改占位"兜底所以用户不可见，但与设计意图不符。
- 修复建议：改用 `lambdaUpdate().set(User::getIsDeleted, 1)` 显式置位；补一条集成测试断言清理后 `is_deleted=1`。

### 13. 二手交易内容不查敏感词

- 位置：`module/trade/service/impl/TradeServiceImpl.publish / edit`（全文无 `sensitiveWordService`）
- 问题：论坛发帖/评论有敏感词拦截，二手标题/介绍/联系方式完全没有；dev 默认 `auto-approve=true` 时零过滤直接上架。
- 修复建议：publish/edit 对 title、description、contact 调 `sensitiveWordService.check`。

### 14. 过期 token 在游客页被强踢去登录

- 位置：`common/auth/AuthInterceptor.java:70-74`（游客路径带无效 token 直接 40101）、`app/frontend/uniappx/uniappx/api/request.uts:80-88`（40101 一律清 token + `navigateTo` 登录页）
- 问题：token 过期的用户逛信息流/商品列表会被踢去登录（本应降级为游客）；一个页面并发多个请求返回 40101 时会叠加 push 多个登录页。
- 修复建议：
  - 后端：游客可读路径上 token 解析失败时按游客放行（不设登录属性），写接口仍严格 401；
  - 前端：40101 跳转去重（全局标志位），并改用 `reLaunch` 避免页面栈堆积。

### 15. 手机号可枚举

- 位置：`module/user/service/impl/AuthServiceImpl:177`（登录报"账号不存在，请先注册"）、`:268-270`（注册场景发码报"手机号已注册"）
- 问题：中间只隔一道图形验证码，可批量探测哪些手机号已注册。
- 修复建议：登录错误统一为"手机号或密码错误"；发码接口的"已注册"提示保留（用户体验优先）但接受可枚举风险并记录决策，或对探测行为加 IP 限频。

### 16. CORS 任意源 + 允许凭据

- 位置：`config/WebMvcConfig.java:60-67`
- 问题：`allowedOriginPatterns("*")` + `allowCredentials(true)`。App 端不受影响，但 admin-web（前端管理端目录已存在，尚为空壳）上线后等于对任意网站开放带凭据跨域。
- 修复建议：admin-web 落地时收紧为域名白名单。

### 17. 敏感词过滤是占位实现

- 位置：`common/sensitive/SensitiveWordServiceImpl.java`
- 问题：`String.contains` 顺序匹配，插空格/变体字/拼音即可绕过；词表仅 8 个演示词；`content-safety.enabled` prod 虽置 true 但无实现消费。
- 修复建议：MVP 接受现状（先审后发 + 人工巡查兜底），但把"接入第三方内容安全"列为上线前待办；词表移入 DB 便于运营维护。

## 五、修复优先级建议

1. **上线三件套**：#1 短信 mock/接入、#2 前端地址、#3 密钥 fail-fast
2. **安全面**：#4 上传限制、#5 IP 取值、#6 换绑二验、#7 管理员密码、#8 上报限频
3. **合规与一致性**：#9 协议页、#10 会话唯一键、#12 软删字段、#13 二手敏感词
4. **体验**：#14 401 降级与跳转去重、#11 热评重复
5. 其余低危随迭代处理
