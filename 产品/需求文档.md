## 1. 产品概述

### 1.1 产品定位

一款面向特定用户群体的社区型 App，提供：

- 管理员发布任务信息，用户浏览后联系管理员；
- 二手物品信息发布与浏览；
- 类似微博的论坛交流；
- 通过接入广告实现变现。

### 1.2 产品形态

| 端 | 使用者 | 说明 |
|----|--------|------|
| App（iOS / Android） | 普通用户 | 仅用户端，无管理入口 |
| Web 管理后台 | 管理员 | 所有管理操作均在 Web 端完成 |

### 1.3 用户规模

- 注册用户约 1 万人；
- 预计日活 500～2000（估算）。日活口径：当日打开过 App 的去重用户数，同一用户每天计 1 次；
- 初期采用：单服务器 + 自建数据库 + 对象存储 + CDN；
- 数据库可选 MySQL / PostgreSQL。

### 1.4 核心目标

- 管理员可高效发布任务、管理二手与论坛内容；
- 用户可浏览任务、联系管理员、发布二手、参与论坛；
- 接入广告并获得收入；
- 保证内容合规、交易风险可控。

## 2. 角色与权限

### 2.1 普通用户

- 注册、登录、编辑个人资料；
- 浏览任务、二手物品、论坛帖子；
- 发布二手物品；
- 发布论坛帖子、评论、点赞、收藏、举报；
- 收藏二手物品、论坛帖子；
- 联系管理员；
- 查看消息通知；
- 查看广告。

### 2.2 管理员

- 仅通过 Web 管理后台登录；
- 权限一致，不设多级权限；
- 发布、编辑、下架、删除任务；
- 审核、下架、删除二手物品；
- 审核、巡查、删除论坛帖子，发布公告，禁言用户；
- 管理用户：查看、封禁、解封；
- 处理举报；
- 配置广告；
- 发布公告；
- 查看数据看板；
- 系统设置。

> 建议至少保留 2 个管理员账号，防止单账号丢失。

## 4. App 功能需求

### 4.1 注册登录与账号

#### 4.1.1 注册登录

登录方式：

- 手机号 + 密码登录（密码在注册流程中设置）；
- 手机号 + 验证码登录（免密登录 / 忘记密码时使用）；
- 未注册手机号在登录时提示"账号不存在，去注册"，不再自动注册（注册走三步流程）；
- 可选支持：微信登录；
- 需勾选同意《用户协议》《隐私政策》。

注册流程：拆分为三个独立页面，顶部步骤条显示"1 手机号 → 2 密码 → 3 昵称"。步骤条状态规则：当前步骤显示数字并高亮，前序步骤显示对勾"✓"，后续步骤保持灰色。

**注册① 手机号验证**

- 输入手机号，获取并输入验证码，点"下一步"进入注册②；
- 页面底部展示短信限频提示（同一手机号 1 分钟 1 条、每日 5 条），与防轰炸规则（7.2）对应。

**注册② 设置密码**

- 密码、确认密码两个输入框，右侧眼睛图标切换明文/密文；
- 密码强度条（三格：弱 / 中 / 强）；
- 密码规则：长度 8～20 位、必须包含字母与数字、建议包含大写字母或符号；
- 底部提示：密码用于登录，建议不要与其他平台相同；
- 点"下一步"进入注册③。

**注册③ 设置昵称**

- 圆形头像上传占位框（可跳过，跳过用默认头像）；
- 昵称输入框，必填，限 12 字，实时字数提示（如"2 / 12"）；
- 性别选填；
- 点"完成注册"后进入 App。

#### 4.1.2 个人资料

- 头像；
- 昵称；
- 性别；
- 个人简介；
- 用户 ID；
- 注册时间。

#### 4.1.3 账号安全

- 忘记密码：登录页入口 → 输入注册手机号 → 验证码校验 → 设置新密码（规则同注册②）；
- 修改密码：设置内可通过旧密码或验证码修改；
- 更换手机号；
- 退出登录；
- 注销账号（MVP 必须，最简版）：设置页入口 → 二次确认 → 提交后 7 天内完成处理，处理期内该账号禁止登录与发布；
- 封禁用户不可登录、不可发布内容。

#### 4.1.4 游客浏览与登录时机

- 未登录（游客）可浏览：交易、任务、论坛内容；
- 需要登录才能操作：发布二手、发帖、评论、点赞、收藏、联系卖家、联系管理员、举报；
- 游客触发需登录操作时，弹出登录引导；
- 好处：降低新用户门槛，应用商店审核人员无需注册即可查看内容。

### 4.2 交易模块

#### 4.2.1 交易首页

从上到下：

- 顶部搜索栏（P1，可先不做）；
- 物品分类：2 排，每排 4 个，共 8 个；
  - 默认分类：数码、家电、服饰、图书、运动、家居、美妆、其他；
  - 分类由 Web 后台可配置（增删改、排序），改动无需发版；
- 广告 Banner：轮播，最多 5 张；
- 交易物品列表：一排两个，双列展示；
- 右下角悬浮按钮：发布二手。

#### 4.2.2 物品卡片

展示：

- 封面图或视频首帧；
- 标题；
- 价格；
- 购买状态标签：
  - 在售：绿色；
  - 已售：灰色；
- 收藏按钮。

不展示"已预定"，不使用橙色状态。

#### 4.2.3 物品详情页

展示：

- 图片/视频轮播；
- 标题；
- 价格；
- 分类；
- 物品介绍；
- 购买状态：在售 / 已售；
- 第三方联系方式：发布时选填，不公开展示（卖家如愿意公开，可在物品介绍中自行写明）；
- 联系卖家：点击后打开与卖家的站内信会话，发送异步留言；卖家在消息通知中看到留言并回复；双方如需微信/电话，通过留言自行交换；
- 收藏 / 取消收藏；
- 举报；
- 卖家操作：编辑、下架、标记已售。

#### 4.2.4 发布二手

字段：

- 标题；
- 图片/视频：最多 9 张图或 1 个视频；图片单张 ≤ 10MB，视频 ≤ 100MB 且时长 ≤ 60 秒（数值为估算，开发前确认）；
- 物品介绍；
- 价格；
- 分类；
- 第三方联系方式（选填，不公开展示；买家通过站内信联系卖家）；
- 是否可议价；
- 状态默认"在售"。

提交后进入审核，审核通过后展示。

#### 4.2.5 我的发布

- 我发布的二手物品；
- 可编辑、下架、标记已售；
- 可查看审核状态：待审核、已通过、已拒绝。

#### 4.2.6 我的收藏

- 收藏的二手物品；
- 收藏的论坛帖子；
- 支持取消收藏。

#### 4.2.7 交易规则

- 初期只做信息撮合；
- 不做平台内支付、担保交易、退款仲裁；
- 页面需加免责声明：交易风险由双方自行承担。

### 4.3 任务模块

#### 4.3.1 任务首页

从上到下：

- 广告 Banner；
- 任务信息流。

#### 4.3.2 任务卡片

只展示：

- 任务标题；
- 任务简述；
- 报酬 / 积分 / 线下结算说明（管理员填写的文字说明，纯展示：平台无积分体系、不涉及任何平台内结算）；
- 发布时间；
- 截止时间；
- 图片、文字等附件。

不展示：

- 任务状态；
- 接单按钮；
- 需要人数 / 已接人数；
- 任何平台内接单操作。

#### 4.3.3 任务详情页

展示：

- 完整任务信息；
- 发布时间；
- 图片/视频附件；
- 报酬说明；
- 截止时间；
- 联系管理员按钮（打开"任务咨询"会话，见 4.5.4）；
- 风险提示文案：「平台仅展示任务信息，请自行甄别真实性，切勿提前支付任何费用」。

用户感兴趣后，通过联系管理员进行后续沟通。App 内不提供接单、不流转任务状态。

#### 4.3.4 Web 后台任务管理

管理员可：

- 发布任务；
- 编辑任务；
- 下架任务；
- 删除任务。

无状态流转、无分配接单、无"我的接单"。

### 4.4 论坛模块

#### 4.4.1 论坛首页

类似微博的信息流，互动操作采用微信朋友圈样式。

页面顶部：

- 顶部为 SVG"发布"图标按钮（替代原搜索位）：点击进入发布帖子页（见 4.4.3）；
- 不设顶部搜索栏；不再使用右下角悬浮加号。

展示：

- 发布者头像、昵称；
- 发布时间；
- 文字内容；
- 图片/视频；
- 高赞评论预览：卡片上直接显示该帖点赞数最高的 1～2 条评论（数值为估算，可调）；
- 视觉层级：高赞评论预览弱化展示（小字号、灰色低调样式，不抢主内容）；点赞数与评论数突出显示（明显字号与位置）。

公告特殊样式（已取消置顶）：

- 管理员发布的公告帖用醒目样式：高亮边框 + 浅色高亮背景 + "公告"角标，与普通帖子一眼区分；
- 最新发布的一条公告固定展示在信息流最顶部，其余公告按时间正常混排（保持醒目样式）。

互动方式（朋友圈样式）：

- 帖子卡片上有 SVG 点赞图标（点击直接点赞/取消点赞）和 SVG 评论图标（点击展开该帖评论并输入）；
- "···"按钮不弹任何菜单（无背景弹层），点击直接跳转举报页面；
- 点赞后头像缩略图显示在卡片上（同朋友圈）；
- 互动图标均不显示文字标签（可在图标旁显示数量）；
- 帖子详情页内可直接操作点赞/评论/收藏/举报，按钮同样只用 SVG 图标。

广告插入：

- 每 5～8 条帖子插入一条信息流广告。

#### 4.4.2 帖子详情页

- 完整文字、图片、视频；
- 点赞；
- 评论；
- 收藏；
- 分享（调用系统自带分享面板，无需额外第三方配置）；
- 举报；
- 评论列表。

#### 4.4.3 发布帖子

进入方式：论坛首页顶部 SVG"发布"图标按钮。

页面内容：

- 文字输入框（必填，建议限 1000 字，估算）；
- 图片/视频：最多 9 张图或 1 个视频（限制与发布二手一致）；
- 发布按钮；
- 发布即展示（不再先审后发）：内容命中敏感词时发布失败并提示修改，未命中直接发布；
- 兜底机制：管理员事后巡查 + 用户举报处理，违规内容删除并视情况禁言；
- 注意：二手物品发布仍为先审后发（不变）。

#### 4.4.4 评论

- 支持文字评论；
- 支持回复评论；
- 评论可点赞：同一用户对同一评论只能点赞一次，可取消后重赞，不重复计数；
- 热评前置：评论展开时，点赞数最高的前 3 条（数值为估算，可调）排在最前并带"热评"标识，其余评论按时间倒序；
- 评论审核口径（统一）：敏感词过滤 + 先发后审。

#### 4.4.5 管理员操作（Web 后台）

- 巡查帖子（先发后审，发现违规直接删除）；
- 处理举报的帖子；
- 删除；
- 禁言用户；
- 发布公告（自动获得公告醒目样式）。

### 4.5 我的模块

页面结构：

- 个人资料卡片：头像、昵称、用户 ID，点击编辑；
- 功能列表：
  - 我的发布；
  - 我的收藏；
  - 消息通知；
  - 联系管理员；
  - 设置。

无"我的接单"；App 内无管理入口。

#### 4.5.1 我的发布

- 我发布的二手物品；
- 我发布的论坛帖子；
- 可查看审核状态。

#### 4.5.2 我的收藏

- 收藏的二手物品；
- 收藏的论坛帖子。

#### 4.5.3 消息通知

类型：

- 系统通知；
- 审核结果；
- 评论/回复提醒；
- 举报处理结果；
- 公告。

MVP 口径：消息通知为 App 内消息中心，进 App 后查看（推送通知为二期 P1）；同时"我的发布"页面直接展示审核状态（待审核 / 已通过 / 已拒绝），确保审核结果不依赖推送也能被用户看到。

#### 4.5.4 联系管理员

- 站内信（MVP 做最简版），三类会话（按类型区分）：
  - **任务咨询**：从任务详情"联系管理员"发起，会话自动关联该任务（显示任务标题，管理员后台能看到咨询的是哪个任务），用于对接工作；
  - **客服咨询**：从"我的 → 联系管理员"发起，不带任务关联，用于一般问题，类似客服；
  - 联系卖家：物品详情"联系卖家"打开与卖家的站内信会话，异步留言，卖家在消息通知中看到并回复；不做实时聊天；
- 三类会话在消息通知中统一展示；管理员 Web 后台可按会话类型筛选，任务咨询优先处理；
- 跳转第三方联系方式：微信、QQ、电话（仅保留管理员/客服入口）。

#### 4.5.5 设置

- 账号安全；
- 隐私政策；
- 用户协议；
- 清除缓存；
- 退出登录；
- 关于我们。

### 4.6 广告模块

#### 4.6.1 广告位

- 交易页 Banner；
- 任务页 Banner；
- 论坛信息流广告：每 5～8 条插入一条；
- 详情页底部广告；
- 插屏广告：每用户每日不超过 3 次；
- 激励视频：可选，用户主动触发。

#### 4.6.2 广告原则

- 不遮挡核心按钮；
- 不强制看广告才能联系卖家；
- iOS 需处理 ATT 隐私授权；
- 国内可接穿山甲、优量汇；
- 海外可接 AdMob；
- 广告需符合平台政策，不诱导点击。

### 4.7 举报与审核

#### 4.7.1 用户举报

可举报：

- 二手物品；
- 论坛帖子；
- 评论；
- 用户。

举报原因：

- 垃圾广告；
- 色情低俗；
- 诈骗；
- 侵权；
- 其他。

#### 4.7.2 审核机制

- 二手物品：先审后发；
- 论坛帖子：先发后审——发布即展示，敏感词过滤拦截 + 管理员事后巡查 + 用户举报兜底；
- 评论：敏感词过滤 + 先发后审（与 4.4.4 统一口径）；
- 图片/视频：接入内容安全审核服务（机审）+ 人工复审，覆盖二手图片/视频、帖子图片/视频、用户头像；
- 审核时效：提交后 24 小时内完成审核（超时提醒管理员处理）；
- 举报：管理员在 Web 后台处理。

#### 4.7.3 处理结果

- 通过；
- 拒绝；
- 删除；
- 封禁用户；
- 通知举报人。

#### 4.7.4 拉黑用户（MVP 必须）

- 入口：用户主页 / 评论头像 → "拉黑"；
- 拉黑后：双方互不可见对方内容（帖子、评论、二手物品），被拉黑方无法评论、私信自己；
- 设置中可查看与解除拉黑列表；
- 背景：苹果审核对用户创作内容类 App 要求具备举报、拉黑、内容过滤三类机制。

## 6. 业务规则与状态

| 对象 | 状态 |

| 二手物品 | 在售（绿）、已售（灰） |

## 7. 非功能需求

### 7.1 性能

- 支持 1 万注册用户、500～2000 日活；
- 接口响应时间：核心接口（列表、详情）P95 < 1 秒，其余接口 < 2 秒；
- 图片/视频使用对象存储 + CDN；
- 视频限制：单视频 ≤ 100MB、时长 ≤ 60 秒（估算，开发前确认）；
- 自建数据库需配置：
  - 每日自动备份；
  - 慢查询日志；
  - 连接数监控；
  - 磁盘容量监控；
  - 定期安全更新。

### 7.2 安全

- HTTPS；
- 敏感词过滤；
- 密码安全：密码禁止明文存储，使用加盐哈希后入库；登录接口错误次数限制（如连续错 5 次锁定 15 分钟，数值需确认）；
- 短信验证码防轰炸：同一手机号 1 分钟最多 1 条、每日最多 5 条，同一 IP 每日设上限（数值需确认）；
- 防刷、防重放；
- 权限校验；
- 管理员强密码 + 二次验证；
- 操作日志。

### 7.3 合规

- 隐私政策；
- 用户协议；
- 广告标识；
- 内容审核；
- 二手交易免责声明；
- 国内需备案、软著等；
- iOS/Android 应用商店上架要求。

### 7.4 推送

- 系统通知；
- 审核结果；
- 评论回复；
- 举报结果；
- 公告。

### 7.5 埋点与数据口径（MVP 最小集）

MVP 必埋 5 个事件（支撑数据看板与复盘，埋点缺失需发版才能补，必须随版本带上）：

| 事件 | 触发时机 | 上报字段 |
|------|----------|----------|
| App 启动 | 冷启动/热启动回到前台 | 用户 ID、时间、App 版本 |
| 页面访问 | 进入交易/任务/论坛/我的等主要页面 | 用户 ID、页面名、时间 |
| 广告曝光 | 广告位成功展示 | 用户 ID、广告位、时间 |
| 广告点击 | 用户点击广告 | 用户 ID、广告位、时间 |
| 发布行为 | 发布二手/帖子/评论成功 | 用户 ID、内容类型、时间 |

口径说明：

- 日活 = 当日打开过 App 的去重用户数；
- 自家看板统计"自家广告位的曝光/点击"；广告收益数据以穿山甲/优量汇等广告平台后台报表为准（看板可人工录入，后续再对接 API）。

## 9. 验收标准

- 用户可注册登录、编辑资料；注册为三步流程（手机号验证 → 设置密码 → 设置昵称，步骤条引导）；登录支持密码与验证码两种方式；设置内提供账号注销入口，提交后 7 天内处理；
- 游客可浏览交易/任务/论坛，发布、收藏、评论、联系等操作触发登录引导；
- 交易页展示 8 个分类、广告 Banner、双列物品流；
- 用户可发布二手，审核通过后展示；
- 物品状态只有在售、已售；
- 用户可收藏、举报；"联系卖家"通过站内信留言完成，物品页不公开展示卖家第三方联系方式；
- 任务页展示广告 Banner 和任务信息流；
- 任务卡片只展示标题、简述、报酬、发布时间、截止时间、附件；
- 任务详情可联系管理员（任务咨询会话，自动关联任务）；
- 论坛支持发帖、评论、评论点赞、点赞、收藏、举报；信息流互动为朋友圈样式（卡片 SVG 点赞/评论图标直接操作，"···"直接跳转举报页，收藏在详情页）；
- 论坛首页顶部为 SVG 发布图标按钮，无搜索栏、无悬浮加号；发布帖子页可发文字与图片/视频，发布即展示（敏感词拦截 + 事后巡查）；
- 帖子卡片上点赞数、评论数突出显示，高赞评论预览弱化展示；评论列表热评前置；公告帖醒目样式、最新一条固定在信息流顶部；无置顶功能；
- "我的 → 联系管理员"为客服咨询会话，与任务咨询在后台可区分、可筛选；
- 论坛信息流每 5～8 条插入广告；
- 我的页面包含个人资料、我的发布、我的收藏、消息通知、联系管理员、设置；
- 无"我的接单"，无 App 管理入口；
- Web 后台可管理任务、二手、论坛、用户、举报、广告、公告；
- 广告正常展示、点击，不遮挡核心操作；
- 管理员操作有日志（记录到具体管理员），支持封禁/解封；
- 支持拉黑用户，拉黑后双方内容互不可见；
- 埋点正常上报：启动、页面访问、广告曝光/点击、发布行为可在数据看板看到数据。

## 11. 风险与注意事项

- 内容审核压力：论坛、二手均需审核，建议机器 + 人工；图片/视频需接内容安全审核服务（按量付费，成本预算需确认）；
- 论坛先发后审风险：违规内容会短暂可见，依赖敏感词过滤 + 巡查 + 举报三层兜底，管理员需养成每日巡查习惯；若违规内容频发，随时可改回先审后发（系统设置已有审核开关）；
- 二手交易纠纷：只做信息撮合，需免责声明；
- 广告政策：避免诱导点击，iOS 需 ATT；
- 上架合规：备案、软著、隐私政策；
- 管理员权限集中：强密码、二次验证、操作日志；
- 单服务器 + 自建数据库存在单点风险；
- 必须做数据库备份与恢复演练；
- 建议数据库不要和 App 完全混部，至少做资源限制；
- 用户量增长后，优先把数据库迁到独立服务器；
- 对象存储和 CDN 可继续使用云服务，降低媒体文件压力。
