## 二、问题（按优先级）

### 问题 1（高）：#21 编辑二手被免登录名单"误伤"，当前完全调不通

`WebMvcConfig` 的免登录名单里写了 `/api/v1/trade/items/*`，本意是放行 **GET** 详情（#19）。但 Spring 拦截器的排除规则**不区分请求方法**，同一路径的 **PUT**（编辑 #21）也被放行了。后果链：

拦截器跳过 → userId 属性永远不会写入请求 → Controller 上的 `@RequestAttribute(userId)` 取不到值 → 抛异常被兜底成 `50000 服务器内部错误`。

也就是说：物主本人拿着有效 token 调编辑，照样报 50000；游客调编辑报的也是 50000 而不是 40101。功能坏了，错误码也不对。（安全上没破口——进不了业务逻辑，`requireOwned` 也拦着，属于"坏"不是"漏"。）

**建议做法**（思路，代码自己写）：
- 根因是"游客可读"和"必须登录"两种需求共用了一套"全放行"机制。标准解法是**双拦截器**：严格版拦默认所有路径（无 token 即 40101）；宽松版只挂在游客可读的 GET 路径上（有 token 就解析出 userId，没有就放行但不设身份）。
- 不想拆两个拦截器的话，最低成本修法：`AuthInterceptor` 里遇到"没有 Authorization 头的 GET 请求"先放行（配合 Controller 里 `required = false` 的取法），无头 PUT/POST/DELETE 仍然拦。缺点是拦截器开始感知请求方法，语义上不如双拦截器干净。
- 顺手把 `GlobalExceptionHandler` 补一个"请求属性缺失"的处理，转成 40101，防止以后同类问题再变成 50000。

**验证方式**：用物主 token 调 PUT /trade/items/{id} 能成功、响应 `auditStatus`；不带 token 调同一接口必须返回 40101；游客 GET 详情仍正常。

### 问题 2（中）：auto-approve 开关上线前必须关

`trade.auto-approve: true` 意味着发布即上架、跳过审核，且媒体行 `auditStatus` 硬编码为"机审通过"（代码注释已声明是占位）。`application-prod.yml` 里没有覆写这个开关——**照现在的配置上生产，任何物品免审直接可见**，与需求 4.7.2"先审后发"冲突。

**建议做法**：在 `application-prod.yml` 显式写 `trade.auto-approve: false`；内容安全接入后，让媒体审核结果与物品状态联动（关联实现注记 5）。两个开关加一句启动日志提醒，防止带着 true 上线。

### 问题 3（中）：#26 上传直传签名未实现，发布流程是"演示通"

发布页能选图选视频，但传给后端的是本地临时路径 / http 直链（`resolveUrl` 对 http 开头原样放行是为种子数据设计的）。OSS 直传（排期 W5）接入前，#20 发布闭环算不通——图片没真正落到对象存储。

**建议做法**：属于排期内欠账，不用现在补，但记住依赖关系：#26（签名）→ 前端 uploadFile → #20 才算真闭环。前端发布页届时要换成"先拿签名 → 直传 OSS → 拿 fileKey 再提交"。
