# MVP 开发顺序清单

**依据**：需求文档 V1.4.1（社区任务与二手交易 App）
**日期**：2026-10-09（2026-10-10 按技术选型更新）
**人力假设**：产品 1、UI 1、App 开发 1（uni-app X）、后端 1～2（Java/Spring Boot）、Web 前端 1（Vue 3）、测试 1
**总周期**：10～12 周（估算）
**用法**：按周对表推进；每个模块带"完成标志"（做完什么算完），避免"感觉快好了"式延期。
**技术栈**：见《架构与技术栈选型》——后端 Java 17 + Spring Boot 3.3 + MySQL 8 + Redis 7；App 端 uni-app X（**W1 先做 3 天技术验证**：广告 SDK 插件 / OSS 直传 / 滚动性能 / iOS 真机，任一失败降级普通 uni-app）。

---

## 〇、三条总原则

1. **资质和开发并行**：营业执照、备案、软著、苹果账号从第 1 周就开始办（见避坑清单第八节），不要等开发完再办——它们比开发慢。
2. **后端比 App 早半步**：每个模块后端接口先出、App 后接，接口文档先行（哪怕先给字段草案），双端不空等。
3. **从最简单的模块打通全链路**：先做"任务"（无状态、最简单），跑通"后台发 → App 看 → 详情 → 联系管理员"的完整链路，把框架问题暴露在最简单的模块上，而不是最难的论坛上。

## 一、周级计划总览

| W3 | 任务模块接口（后台发布/编辑/下架/删除 + App 列表/详情） | 任务首页（Banner 位）、任务详情、联系管理员（任务咨询会话） | 任务管理页 | M2 验收：全链路首次打通 |

| W8 | 论坛接口②：评论（两级+点赞+热评排序）、拉黑、举报流转 | 帖子详情、发布帖子页、评论列表、举报页 | 举报管理 | M4 验收：论坛模块完成 |
| W9 | 我的模块：个人资料编辑、账号安全（注销/修改密码/换手机号）、设置；埋点上报接口 | 我的页面全套、个人资料、设置、拉黑列表 | 数据看板（读埋点数据） | 全功能联调开始（M5） |
| W10 | 广告接入（Banner/信息流/插屏）：先自家广告位表+开关，再接 SDK | 广告位嵌入、ATT 弹窗（iOS） | 广告管理（配置/开关） | 功能回归测试一轮 |
| W11 | 备份恢复演练、性能压测（列表/详情 P95<1s）、安全自查 | Bug 修复 | 看板数据核对 | 全面测试（功能/兼容/安全） |

## 二、模块开发顺序与理由

| 顺序 | 模块 | 为什么排这里 | 完成标志 |
|------|------|--------------|----------|
| 1 | 注册登录（三步流程） | 一切的入口；短信服务、会话、鉴权都在这里立起来 | 三页注册+双通道登录+忘记密码全通，限频生效 |
| 2 | Web 后台框架 | 管理员没有后台，后面所有"后台发布/审核"都没法测 | 管理员可登录，操作日志落库 |
| 3 | 任务模块 | 最简单（无状态流转），用来打通全链路 | 后台发任务 → App 看到 → 详情 → 发起任务咨询 |
| 4 | 交易模块 | 第二简单，但包含审核流、机审、站内信三个重头组件 | 发二手 → 机审+人审 → 展示 → 买家站内信联系卖家 |
| 5 | 站内信系统 | 交易和论坛都依赖它（联系卖家/客服），单独成系统 | 三类会话收发、后台回复、消息中心可见 |
| 6 | 论坛模块 | 最复杂（互动多、样式多），放在后段，此时框架已稳 | 发帖即展示、朋友圈式互动、热评、公告样式、举报闭环 |
| 7 | 我的模块 | 多为已有能力的拼装页（跳列表+账号操作） | 资料编辑、注销、拉黑列表、设置全通 |
| 8 | 广告+埋点 | 最后接，但 W9 前账号必须就绪；埋点必须随版本带上（7.5） | 广告位可配置可开关，看板能看到 5 类埋点数据 |
| 9 | 测试+上架 | 前 8 项完成后再全面测试 | M6：双端提审 |

## 三、每个模块的坑点提示（对应避坑清单）

| 模块 | 做之前先看避坑清单哪条 |
|------|------------------------|
| 注册登录 | 短信限频（Top1）、验证码前置图形验证、密码加盐哈希、忘记密码必须有 |
| 任务模块 | 任务详情风险提示文案、联系管理员自动关联任务 |
| 交易模块 | 价格用"分"存（Top5）、图片压缩+对象存储（Top3）、软删除字段、联系方式接口不下发 |
| 站内信 | 拉黑用户后不可发留言（与 4.7.4 联动）、会话表设计要区分三类 |
| 论坛 | 评论只做两级、信息流游标分页、点赞防连点、敏感词库后台可维护（先发后审的兜底） |
| 我的 | 注销 7 天处理期、操作日志到人 |
| 广告 | SDK 需个体户资质账号（先确认已过审）、iOS ATT 弹窗顺序、广告位总开关 |
| 上架 | iOS UGC 三件套齐全（Top4）、隐私政策 URL 可访问、审核演示说明 |

## 四、里程碑

| 里程碑 | 时间 | 标准 |
|--------|------|------|
| M1 | W1 末 | 环境、数据库设计定稿、三端骨架能跑 |
| M2 | W3 末 | 注册登录可用，任务模块全链路打通（第一次端到端） |
| M3 | W6 末 | 交易模块端到端（含审核流、机审、站内信） |
| M4 | W8 末 | 论坛模块完成 |
| M5 | W9 末 | 功能全部完成（Feature Complete），进入联调 |
| M6 | W11 末 | 测试通过、备份恢复演练完成、提审 |

里程碑延期处理规则：M2～M4 每个里程碑_delay 超过 3 天，砍二期功能（搜索/推送等本来就在二期），**不砍**敏感词过滤、限频、拉黑这三条合规底线。
